# راهنمای UI/UX سامانه — Gauzy-inspired

## هدف
این سند مرجع اجرایی رابط کاربری سامانه اتوماسیون رستوران است. طراحی از الگوهای عمومی و حرفه‌ای موجود در Ever Gauzy الهام می‌گیرد؛ شامل Shell مدیریتی، Sidebar، Header، Breadcrumb، داشبورد ویجتی، کارت‌های آماری، جدول‌های مدیریتی، حالت‌های Loading/Empty/Error و Theme قابل تغییر. هیچ کد یا هویت بصری Gauzy کپی نمی‌شود.

## اصول طراحی
- RTL واقعی و فارسی‌محور
- Desktop-first برای پنل مدیریتی، Responsive برای تبلت و موبایل
- کاهش تعداد کلیک در POS و عملیات پرتکرار
- سلسله‌مراتب بصری روشن و تراکم کنترل‌شده
- استفاده از کارت، Badge، Table، Drawer، Modal و Toast با رفتار استاندارد
- عدم اتکا فقط به رنگ برای انتقال وضعیت
- Keyboard navigation و Focus قابل مشاهده
- Dark/Light theme
- طراحی مبتنی بر Permission: آیتم و عملیات بدون مجوز نمایش داده نشوند

## App Shell
1. Sidebar ثابت/جمع‌شونده در دسکتاپ
2. Header شامل عنوان/مسیر صفحه، جستجوی سریع، اعلان‌ها، انتخاب شعبه/صندوق، Theme و پروفایل
3. محتوای اصلی با یک Scroll surface
4. Breadcrumb برای صفحات عمیق
5. صفحه‌ها از Layout مشترک استفاده کنند و از تکرار Header/Sidebar پرهیز شود.

## Sidebar
گروه‌ها:
- داشبورد
- فروش: سفارش‌ها، صندوق، فاکتورها
- مشتریان
- منو و محصولات
- سالن و میزها
- آشپزخانه
- انبار و خرید
- مالی
- گزارش‌ها
- دستگاه‌ها و چاپ
- کاربران و دسترسی‌ها
- تنظیمات
- Audit Log

Sidebar باید:
- وضعیت Active را واضح نشان دهد
- قابلیت Collapse داشته باشد
- گروه‌های تو‌در‌تو را با Accordion مدیریت کند
- روی موبایل به Drawer تبدیل شود.

## Dashboard
داشبورد بر اساس نقش شخصی‌سازی می‌شود. مدیر شاخص‌های فروش/مالی/عملیاتی، صندوقدار وضعیت صندوق و سفارش‌ها، انباردار موجودی و خرید، و آشپز صف آماده‌سازی را می‌بیند.

ویجت‌های پایه:
- فروش امروز
- تعداد سفارش
- میانگین مبلغ سفارش
- مشتریان
- سفارش‌های در انتظار
- وضعیت آشپزخانه
- موجودی کم
- آخرین سفارش‌ها
- میانبر عملیات

## جدول‌ها
- Toolbar با Search، Filter، Sort، Refresh و Export بر اساس Permission
- Pagination
- ستون Actions با منوی عملیات
- Badge برای وضعیت
- Row selection فقط در صفحات لازم
- Empty state و Loading skeleton
- در موبایل تبدیل به Card/List یا اسکرول افقی کنترل‌شده

## POS
POS باید سه ناحیه داشته باشد:
1. دسته‌بندی و جستجوی سریع
2. اقلام سفارش
3. خلاصه، تخفیف، مالیات و پرداخت

در نمایش کوچک، ناحیه سوم به Bottom Sheet/Drawer تبدیل شود. دکمه‌های لمسی حداقل 44px باشند.

## فرم‌ها
- Label واضح
- Validation لحظه‌ای
- خطای فارسی نزدیک فیلد
- حفظ ورودی در خطا
- وضعیت Disabled/Loading برای Submit
- Confirm برای عملیات برگشت‌ناپذیر

## وضعیت‌ها
هر صفحه باید Loading، Empty، Error و Success state داشته باشد.

## رنگ و Typography
رنگ پایه خنثی و یک Primary Accent، با رنگ‌های معنایی Success/Warning/Danger/Info. رنگ‌ها در CSS Token تعریف شوند و در Dark Mode جایگزین داشته باشند. فونت فارسی ترجیحاً Vazirmatn در صورت فراهم بودن، با fallback سیستم.

## دسترس‌پذیری
کنتراست مناسب، Focus ring، متن جایگزین برای آیکون‌های بدون متن، Keyboard navigation، aria-label برای کنترل‌های آیکونی و عدم انتقال مفهوم صرفاً با رنگ.

## قواعد اجرایی
- Componentها قابل استفاده مجدد باشند.
- کلاس‌های CSS مبتنی بر نقش/Component باشند، نه وابسته به صفحه.
- JS بدون وابستگی سنگین و Progressive Enhancement باشد.
- UI نباید منطق کسب‌وکار یا Permission را دور بزند؛ کنترل امنیت در Backend الزامی است.
